# Truth Sources

This document names Ollmo's main truth sources and how they relate. It is a small operational matrix, not a replacement for `docs/PRINCIPLES.md` or `docs/CORE_CONTRACTS.md`.

Core rule: model prose is evidence. Runtime-owned files, frames, contracts, artifacts, and live process facts decide truth.

## Authority Order

When sources disagree, use the narrowest source that owns the fact:

1. **Live runtime fact** for process, port, backend health, and currently usable model state.
2. **Final saved artifact file** for artifact bytes and file content.
3. **Response frame / late fill closure truth** for what the response owed, fulfilled, blocked, waived, superseded, or left repair-needed.
4. **Artifact registry / dossier** for artifact identity, provenance, metadata, enrichments, and lookup.
5. **Stable registry** for configured/running instance identity and durable model metadata.
6. **Volatile status/cache** for readiness, activity, timing, cooldown, and last-error projections.
7. **UI, history, compact lookup, logs, and events** as projections or audit support unless a contract below says otherwise.

## Closure Repair Payload Truth

Closure-promoted text artifact repairs are evidence packets, not generic retry prompts. A repair branch should receive the target artifact identity/path, the concrete defect class, and the current saved bytes needed to patch or replace only that target.

- Syntax repair carries deterministic syntax issues plus the current saved target file content.
- Link rebind carries unresolved placeholders or guessed links, concrete runtime artifact paths, and the current saved target file content.
- HTML/CSS selector-binding repair carries the CSS target, linked HTML artifact, HTML classes not targeted by CSS, CSS class selectors not present in HTML, and the current saved HTML and CSS content.

Those payloads are subordinate to final saved artifact bytes and response-frame closure truth. They should preserve valid runtime artifact links, copy, layout intent, and unrelated structure. If a repair branch receives broad root-prompt or `current_phase_output` context that contradicts the bounded closure payload, the bounded closure payload wins.

## Post-Response Substrate Hygiene

Post-response substrate hygiene is currently enabled by default in conservative mode through `OLLMO_POST_RESPONSE_SUBSTRATE_UNLOAD`.

- Unset, `conservative`, `on`, or `true` means conservative hygiene.
- `off`, `false`, `0`, `disabled`, or `no` disables it.
- Conservative hygiene only targets loaded model memory for response-related idle instances. It must not edit durable truth files, response frames, artifact registries, history, or artifact bytes.
- For Ollama, the unload action is `keep_alive: 0`; for MLX backends, Ollmo uses an advertised unload URL when the runtime metadata says unload is supported.
- Busy instances are skipped.

## Cleanup Classes

Cleanup should use explicit classes instead of one broad meaning of "clean":

- **Cache/status cleanup**: volatile status, temporary caches, derived indexes that can be rebuilt.
- **Log/event cleanup**: diagnostics that can be archived or trimmed without changing artifact/frame truth.
- **User-work cleanup**: artifacts, response frames, artifact registry, and history. This needs explicit forget/reset/archive-first semantics.
- **Protected Ghost-state cleanup**: Ghost preferences, compiled memory, bounded self-learning state, and learning-owned retained sidecars. `archive --full` may snapshot these files but must preserve active checkout copies; explicit Ghost forgetting and learning reset remain separate commands. Response-frame sidecars reachable from active learning must be retained or reported missing before response-frame cleanup.
- **Lifecycle cleanup**: stopping processes or freeing model memory. This needs explicit lifecycle intent.

Treat cleanup commands as operationally meaningful, not passive observation.

## Observer And Refresh Truth

Read/status/preview surfaces default to **observer/cached truth**. Observer reads may use `model_ports.json`, existing `state/runtime_status.json`, in-memory request state, frames, registries, history, logs, and artifacts, but they must not write status files, probe backend ports, fetch backend runtime metadata, start/stop/unload models, recover the control plane, or execute response work. `/api/runtime_status` is part of this observer set: by default it reads cached entries from `state/runtime_status.json`, including `instance_id` lookups, and does not refresh or rewrite the file.

Explicit `refresh=true` requests opt into **refresh truth**. Refresh may probe local process/port/backend facts and update `state/runtime_status.json`, but it is still not execution: runtime-status reads and route preview with refresh may use fresher runtime facts, but must not start, stop, unload, materialize branches, write artifacts, or freeze response frames.

Ghost route preview semantic compute is controlled by a non-UI policy. `OLLMO_GHOST_PREVIEW_COMPUTE_SEMANTICS` accepts `off`, `on`, or `auto`; unset or invalid values default to `off`, and `auto` currently behaves like `on`. When the request omits `compute_semantics`, that policy decides whether preview may use **computed preview truth**. Explicit `compute_semantics=true` still opts into compute even when the default policy is `off`. Explicit `compute_semantics=false` is the standard pure cached/passive preview escape hatch because `OLLMO_GHOST_PREVIEW_COMPUTE_SEMANTICS_FALSE_OVERRIDE` defaults to `allow`; operators can set it to `deny` to keep an active `on` or `auto` policy in force despite explicit false. The automatic UI route-preview observer sends `compute_semantics=false` so frequent Auto-target resolution stays passive. In preview metadata, `semantic_compute_requested` is the effective resolved permission after explicit-request and policy handling, not merely the raw request flag; `semantic_compute_performed` separately records whether helper work actually ran. Computed preview may call embedding or semantic helper backends for route-quality signals, but the evidence remains preview-only, non-learnable by default, and still must not execute response work, lifecycle actions, materialization, artifact writes, or response-frame writes. `refresh=true` and semantic compute are independent; refresh alone must not imply semantic helper compute.

Execution truth remains separate and starts only through execution or lifecycle surfaces such as `/api/responses`, explicit model start/stop/remove actions, branch materialization, artifact writes, and response-frame persistence.
